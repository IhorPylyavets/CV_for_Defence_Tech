# ДЗ 6 · Grounded-SAM 2: маски динамічних об'єктів на відео без донавчання

До [заняття 6](../../lessons/06-zero-shot-segmentation/). ≈ 2 години, 15 балів, без формул.

Ноутбук: [`02_grounded_sam2_video_student.ipynb`](02_grounded_sam2_video_student.ipynb), ядро **Python (cv-advanced)**.
Бажано GPU (на RTX 5090 — кілька хвилин). На CPU ноутбук сам зменшує обсяг: 10 / 20 кадрів dev / test замість 15 / 30,
кожен четвертий кадр кліпу замість кожного другого, до 8 об'єктів у замірі 4.2 — повний прогін на 32 ядрах ≈ 35 хв.

Дані й ваги (≈ 2 ГБ) — один раз, з кореня репозиторію:
```bash
python tools/fetch_visdrone.py --splits val            # VisDrone2019-VID-val: кліп для частин 1–4
python tools/fetch_visdrone.py --dataset visdrone-det  # VisDrone2019-DET-val: dev / test для промптів
python tools/fetch_sam_models.py --models sam2.1-small
python tools/fetch_ov_models.py --models gdino-base
```

| Частина | Кроки | Слайди |
|---|---|---|
| 1 · промпт → бокси | Grounding DINO на ключовому кадрі → 3+ формулювання → вибір на 15 кадрах dev → P / R на 30 кадрах test | «Механіка текстового промпта», «Prompt engineering під домен», «Як чесно виміряти zero-shot на своїх даних» |
| 2 · бокси → маски | фільтр боксів і `MAX_OBJ` → SAM 2.1: усі бокси одним батчем | «Grounded-SAM: класична композиція», «Три режими в коді: SAM 2.1 image API» |
| 3 · поширення | SAM 2 по кліпу (60 кадрів, на CPU — 30), оцінка за GT-треками VisDrone → корекція одним боксом у середині | «SAM 2: архітектура з пам'яттю», «Promptable Visual Segmentation» |
| 4 · експорт і вартість | маски PNG, вирізання, `overlay.mp4`, COCO RLE → мс по вузлах і від `n_obj` (код готовий) | «Композиція в 15 рядках і її latency-бюджет», «SAM 2 чи класичний трекер?» |
| 5 · питання | два провали з гіпотезою й прийомом із каталогу; чи полетить це на борт | «Каталог провалів: що робити», «Правильне місце zero-shot у продакшені» |

Кліп — `uav0000305_00000_v`, кадри 60…178 (кожен другий; на CPU — кожен четвертий), 1904 × 1071: десятки машин, частина ховається одна за одну.
У кожному з 10 TODO — один виклик моделі, умова або значення параметра; після кожного кроку `check()` показує ✅/❌.
Таблиці з числами друкує сам ноутбук — переписувати їх не треба; пишете лише висновок до 1.3 і відповіді в частині 5.
Розмітка VisDrone відіграє роль «50 ручних кадрів» зі слайда: однакова для всіх і чесніша за розмітку за вечір.

не оцінюється.

**Здати** — **один архів** `dz6_<прізвище>.zip`, прикріплений в особистому кабінеті LMS. В архіві: ноутбук з виводами
(Kernel → Restart & Run All, потім зберегти) із відповідями в клітинках «✍️», і файли
`outputs/export/overlay.mp4` та `outputs/export/annotations.json` (≈ 8 МБ разом). Архів збирає остання клітинка ноутбука
(розділ «Здача»): впишіть прізвище в `SURNAME` і запустіть її після збереження. Окремі файли, посилання на диск чи
репозиторій не приймаються.

[`solution/`](solution/) — розв'язок для викладача. На RTX 5090: усі перевірки проходять, повний прогін — кілька хвилин.
На dev найкращий промпт `vehicle .` (F1 0.72 проти 0.44 у базового й 0 у промпта з комою); SAM 2 веде 15 машин
з медіанним IoU 0.79, корекція одним боксом прибирає 12 проблемних кадрів; T_frame для 16 об'єктів ≈ 128 мс (≈ 8 FPS).
